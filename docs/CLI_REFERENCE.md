# steemvmd CLI reference

Every `steemvmd tx ...` and `steemvmd query ...` subcommand available on this chain, module by
module, generated by reading the actual wiring in this repo (`app/app_config.go`,
`x/*/module/autocli.go`, `proto/**/tx.proto` and `query.proto`, and — for standard Cosmos SDK /
cosmos/evm / ibc-go modules that aren't reimplemented here — the vendored `client/cli` packages at
the exact pinned versions this chain builds against: `cosmos-sdk v0.54.3`, `cosmos/evm v0.7.1`,
`ibc-go v11.0.0`). It is not generic Cosmos SDK documentation; command names, positional-arg order,
and flags can and do differ by SDK version and by this chain's own customizations, and everything
below was checked against source rather than assumed.

This complements [`Instructions/ORACLE_COMMANDS.md`](../Instructions/ORACLE_COMMANDS.md), which is a
narrower, task-oriented walkthrough of the bridge/oracle attestation duty cycle. Nothing here
contradicts it; this document is the exhaustive module-by-module reference.

## Conventions used below

- Chain-id: `steemvm`. EVM chain-id: `8163` (`0x1fe3`). Bech32 prefix: `steem` (validator operator
  addresses: `steemvaloper1...`; consensus addresses: `steemvalcons1...`). Base denom: `asteem` (18
  decimals, display `steem`). Bridged SBD denom: `asbd` (18 decimals, display `sbd`).
- Every `tx` command below additionally accepts the standard Cosmos SDK tx flags
  (`--from`, `--chain-id`, `--home`, `--keyring-backend`, `--gas`, `--gas-adjustment`,
  `--gas-prices` or `--fees`, `--node`, `--broadcast-mode`, `-y`, `--generate-only`, `--dry-run`,
  etc.) — these are not repeated per command.
- Every `query` command additionally accepts `--node`, `--height`, `--output json|text`, and (where
  a response is paginated) `--page`, `--limit`, `--offset`, `--count-total`, `--reverse`.
- `[positional]` = required positional argument, in order. `<optional>` = optional positional
  argument. Flags are `--long-form`.
- "Gov-gated" / "authority-gated" means the message's only valid signer is the `x/gov` module
  account, so it is never sent directly — it is wrapped in a `tx gov submit-proposal` JSON payload.
  Such RPCs are `Skip: true` in the module's `autocli.go` (or otherwise have no direct CLI leaf) and
  are not given their own top-level command.

## 1. Custom modules

### 1.1 `steembridge` (Go package `x/oracle/bridge`, proto package `steemvm.steembridge.v1`)

The attestation-based Steem↔SteemVM bridge, plus the Steem name-service used for validator identity.
Bonded validators independently observe Steem and submit attestations; deposits, withdrawal payouts,
and name registrations all resolve once confirmations reach `bridge_confirmation_threshold` (default
2/3) of bonded voting power. The gateway account is the hardcoded Go constant `svm.bank`
(`x/oracle/bridge/types.GatewayAccount`) — **never governance-settable**; the `gateway_account` param
below is wire-only, kept for informative genesis/query output. The module account name/store key
stays `steembridge` even though the Go package lives under `x/oracle/bridge` (a v0.0.3 code
relocation, not a consensus change).

**Fee exemption:** `attest-deposit`, `attest-withdrawal-payout`, and `submit-name-registration` ride
free for bonded validators (a shared per-validator, per-block cap of up to 100 free attestations —
see `app/ante_steembridge.go`); `confirm-name` similarly rides free for the confirming destination
address, under its own per-confirmer per-block cap. Any tx that doesn't qualify (message content
rejected, cap exhausted, non-bonded signer) falls through to the normal fee path, so
`--gas-prices`/`--fees` should still be supplied as a fallback. `bridge-out` is never fee-exempt.

#### Tx

| Command | Positional args | Notes |
|---|---|---|
| `attest-deposit` | `[txid] [op-index] [steem-block] [steem-timestamp] [steem-sender] [gateway-account] [amount-millisteem] [memo] [asset]` | Bonded-validator-only attestation of a Steem gateway deposit. Signer (`--from`) is the `validator` field, a bech32 **account** address. `gateway-account` must equal `svm.bank` (the hardcoded constant) or the attestation fails fact-matching. `amount-millisteem` is STEEM/SBD's native 3-decimal unit (`1000.000 STEEM` → `1000000`). `memo` is copied verbatim from Steem — it decides the mint destination in consensus. `asset` is `BRIDGE_ASSET_STEEM` or `BRIDGE_ASSET_SBD`. At threshold, mints `asteem` or `asbd` (10^15 × amount-millisteem) to the memo-derived destination. |
| `bridge-out` | `[destination-steem-account] [amount-asteem] [memo] [asset]` | Burns the caller's `asteem` (or `asbd` if `asset=BRIDGE_ASSET_SBD` — the positional name `amount-asteem` is historical; the amount is in whichever asset's base denom you select) and creates a `REQUESTED` `Withdrawal` record. No automatic Steem-side payout — a validator must relay it manually and then attest via `attest-withdrawal-payout`. If unattested within `withdrawal_timeout_blocks` (default ~3.5 days), the chain auto-refunds the net amount with no attestation/governance action required (`Keeper.RefundExpiredWithdrawals`, `keeper/abci.go`). |
| `attest-withdrawal-payout` | `[withdrawal-id] [steem-txid] [op-index] [steem-block] [steem-timestamp]` | Bonded-validator-only attestation that the gateway's Steem payout (memoed `svm-withdrawal <id>`) happened. At threshold flips the `Withdrawal` REQUESTED → PROCESSED. A late attestation on an already-`REFUNDED` withdrawal is a benign no-op (never double-pays) but emits `withdrawal_payout_attested_after_refund` for audit visibility. |
| `submit-name-registration` | `[txid] [op-index] [steem-block] [steem-timestamp] [steem-account] [gateway-account] [amount-millisteem] [memo]` | Bonded-validator-only attestation of a Steem→gateway transfer requesting a name link. Same shape as `attest-deposit` minus `asset`, with `steem-account` (the Steem username being linked) replacing `steem-sender`. At threshold moves the registration PENDING → `AWAITING_CONFIRMATION` (does not mint or link anything by itself). |
| `confirm-name` | `[registration-id]` | Signed by the memo-derived destination address (**not** a validator duty). Activates the `steem_account → address` link, moving the registration to `ACTIVE`. Required before that address's operator can create a validator (see §2.3 below). |
| `update-params` | — | `Skip: true` in autocli — gov-authority only, no direct CLI leaf. Update via `tx gov submit-proposal` with a `MsgUpdateParams` payload. |

### 1.2 `oracledata` (Go package `x/oracle/data`, proto package `steemvm.oracle.data.v1`)

The commit-reveal price-feed module. Bonded validators submit a hash commit
(`aggregate-exchange-rate-prevote`) one vote period, then reveal the matching salt+rates in the
**immediately following** vote period (`aggregate-exchange-rate-vote`); the power-weighted median of
in-band reveals becomes the on-chain rate for each whitelisted pair. **Not fee-exempt** — unlike the
bridge attestations, these txs always need a real `asteem` balance and `--gas-prices`.

**Footgun:** the `validator` field/positional arg in every message and query here is the bech32
**account** address (`steem1...`), never the operator/valoper address (`steemvaloper1...`) — this is
easy to get backwards coming from `x/staking` conventions.

#### Tx

| Command | Positional args | Notes |
|---|---|---|
| `aggregate-exchange-rate-prevote` | `[validator] [hash]` | Commits `hash = sha256(f"{salt}:{exchangeRates}:{validator}")`, hex, truncated to 40 chars (see `oracle/PROTOCOL.md` §7 for the exact cross-language spec). `validator` = bech32 **account** address, bonded-validator-only. |
| `aggregate-exchange-rate-vote` | `[validator] [salt] [exchange-rates]` | Reveal. `exchange-rates` is a sorted `"PAIR:rate,PAIR:rate,..."` CSV; `salt` and the string must exactly match the prior period's prevote hash. Must land in the vote period immediately after the matching prevote — a missed window is not late-revealable, it's simply abandoned. Whitelisted pairs (per default params): `STEEM/USD_External`, `STEEM/SBD_Internal`, `SBD/USD_External`, `Price_Feed` (Steem's own witness-median feed price — not a tradeable pair). |
| `update-params` | — | `Skip: true` — gov-authority only. |

#### Query

| Command | Positional args | Purpose |
|---|---|---|
| `params` | — | `vote_period`, `vote_threshold`, `reward_band`, `miss_band`, `whitelist`. |
| `exchange-rate` | `[pair]` | The finalized power-weighted-median rate for one pair, e.g. `STEEM/USD_External`. |
| `exchange-rates` | — | All finalized rates. |
| `aggregate-prevote` | `[validator]` | A validator's current uncommitted prevote (hash + submit height). `validator` = account address. |
| `aggregate-vote` | `[validator]` | A validator's current revealed vote (all pairs). `validator` = account address. |

### 1.3 `oracle` (parent module, Go package `x/oracle`, proto package `steemvm.oracle.v1`)

The unified slashing engine both duty modules (`steembridge` attestations, `oracledata` price
votes) report participation into, evaluated once per `SlashWindow` with an anti-masking
`DutyFloor` (`x/oracle/types/eval.go`). **No user-facing CLI at all**: the module has no
`query.proto`/`Query` service and no `x/oracle/module/autocli.go`, so there is no `steemvmd query
oracle ...` namespace. Its only RPC, `MsgUpdateParams`, is gov-authority-gated with no dedicated CLI
leaf (submit via `tx gov submit-proposal`). Its slashing/jailing effects are visible indirectly
through `query slashing signing-info` / `query staking validator` on affected validators.

### 1.4 `steemvm` (Go package `x/steemvm`, proto package `steemvm.steemvm.v1`)

An ignite-scaffolded placeholder module — effectively just a `Params` container, not part of the
bridge/oracle stack. Do not confuse with `steembridge`.

| Kind | Command | Notes |
|---|---|---|
| Query | `params` | Shows the module's (currently unused) parameters. |
| Tx | `update-params` | `Skip: true` — gov-authority only, no direct CLI leaf. |

### 2.3 `staking`

**Chain-specific gate:** `create-validator` and `edit-validator` pass through
`app/ante_steembridge.go`'s `steembridgeValidatorGateDecorator` before reaching the staking
handler. Unless `steembridge`'s `name_service_enabled` param is off, `MsgCreateValidator` is
rejected unless the validator's `moniker` is an **ACTIVE** name-service link (`confirm-name`
already run) owned by that exact operator account, **and** `Description.details` embeds all three
Steem keys in the literal form `owner=STM...;active=STM...;posting=STM...`. `edit-validator` is
validated the same way on the *effective* post-edit moniker/details (an edit that leaves both at
`types.DoNotModifyDesc` is unaffected and always passes) — so the identity can be set but never
silently stripped. Genesis validators are exempt (steembridge's `Params` isn't set yet when genesis
gentxs are delivered — see `x/oracle/bridge/keeper/validator_identity.go`).

## 6. Fee-exemption / permission cheat sheet

| Message | Signer | Fee-exempt? | Gate |
|---|---|---|---|
| `steembridge attest-deposit` | bonded validator (account addr) | Yes, capped ~100/validator/block | Rejected if not bonded, wrong gateway/asset/amount, or cap exhausted |
| `steembridge attest-withdrawal-payout` | bonded validator (account addr) | Yes, same shared cap | Same as above |
| `steembridge submit-name-registration` | bonded validator (account addr) | Yes, same shared cap | Same as above; also requires `name_service_enabled` |
| `steembridge confirm-name` | the registration's derived destination address | Yes, capped per confirmer/block | Must be an AWAITING registration destined to this exact signer |
| `steembridge bridge-out` | any account | No | Requires `bridge_out_enabled`, amount within min/max bounds |
| `oracledata aggregate-exchange-rate-prevote` / `-vote` | bonded validator (**account** addr, not valoper) | No | Bonded-validator-only at the message level; wrong reveal window/hash rejected |
| `staking create-validator` / `edit-validator` | account submitting the msg | No | Steem identity gate (§2.3) unless `name_service_enabled` is off; genesis validators exempt |
| Everything else in this document | per-module normal rules | No | Standard SDK/IBC/EVM authorization |
